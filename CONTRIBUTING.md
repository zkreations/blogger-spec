# Contributing to blogger-spec

`blogger-spec` is the canonical, standalone, zero-runtime-dependency specification authority for Blogger XML templates and expressions.

---

## Core Invariants

1. **Catalogs are the SSOT**: All rules, directives, operators, and types live in [`catalogs/<catalog>.json`](catalogs/). Never hardcode spec knowledge in `src/`.
2. **Never Edit Generated Artifacts Directly**: `fixtures/index.json` and `dist/` are generated by `pnpm run build`.
3. **Zero Runtime Dependencies**: Production exports must maintain `"dependencies": {}` in `package.json`.
4. **Empirical Verification**: Any spec change or fix requires a corresponding fixture in [`fixtures/`](fixtures/) with evidence attribution (`official` or `observed`).

---

## Architecture Overview

```
blogger-spec/
├── catalogs/                 # Canonical Single Source of Truth (9 master JSON catalogs)
│   └── schemas/              # JSON Schemas (Draft 2020-12) for each catalog
├── fixtures/                 # Empirical conformance test cases
│   ├── expressions/          # Expression evaluation fixtures
│   ├── templates/            # Template rendering fixtures
│   ├── diagnostics/          # Negative validation fixtures (rejected by Blogger)
│   └── index.json            # Compiled fixtures manifest (generated)
├── src/                      # TypeScript modules (AST, helpers, runner, tooling)
└── dist/                     # ESM bundles and generated type definitions
```

## Contribution Workflow

### 1. Catalog Changes
- **Directives & Attributes**: Edit [`catalogs/directives.json`](catalogs/directives.json).
- **Operators**: Edit [`catalogs/operators.json`](catalogs/operators.json) (both `precedence_hierarchy` and `operators` map).
- **Schemas**: If the catalog metadata structure changes, update [`catalogs/schemas/`](catalogs/schemas/).

### 2. Add Conformance Fixture
Add a test case under [`fixtures/`](fixtures/) adhering to the `BloggerFixture` schema (`input`, `expected`, `covers`, `verifiedAt`).

### 3. Build & Verify
Run the validation pipeline:

```bash
pnpm run build        # Regenerates fixtures/index.json and dist/index.d.ts
pnpm run test:spec   # Validates JSON schemas (AJV), referential integrity & freshness
pnpm run typecheck   # Type-check TypeScript
pnpm run lint        # Code style check
pnpm run test        # Runs test suite
```

## Reporting Issues

Use the GitHub Issue templates when submitting reports:

- **[Specification Inconsistency](.github/ISSUE_TEMPLATE/spec_inconsistency.md)**: Discrepancies between `blogger-spec` and the actual Blogger engine.
- **[New Spec Entity Discovery](.github/ISSUE_TEMPLATE/new_spec_entity.md)**: Newly discovered operators, directive attributes, or globals.

---

## Commit Guidelines

Follow [Conventional Commits](https://www.conventionalcommits.org/):

- `feat(catalog)`: New directive, operator, or type.
- `fix(catalog)`: Correction to an existing attribute, precedence, or constraint.
- `test(fixtures)`: New or updated conformance fixtures.
- `docs`: Documentation updates.
- `chore`: Tooling or build maintenance.
